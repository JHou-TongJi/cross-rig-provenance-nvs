# l4-se 次要空间转换方案：代码、环境与复现说明

提交包中的 `l4-se_code/` 是当前次要/备选空间转换方案的稳定代码快照。主方案是同一提交包中的 GCR-NVS 深度学习路线；本代码包不是历史试验代码的全集，而是围绕 `reconstruct_rig_api` 整理出的几何基线、回退路径和可复现主链。

`l4-se` 的核心价值是证明本赛题的数学基础与解题思路：把坐标、标定、LiDAR、RGB-D、七相机刚性关系和 SE(3) 视角转换讲清楚，并输出可审计的几何结果。它是主方案的几何骨架，不承担主方案中 DA3/T0/DINOv2/AnyUP 学习增强和 residual-hole 生成补全的最终效果声明。

## 当前冻结版本

当前版本采用共享七相机刚性 rig：

```text
T_L_Ci_view = T_L_R_view @ T_R_Ci_mount
```

主链顺序是：

```text
源 RGB + camera_config + K/D + LIDAR_CONCAT
 -> K' 去畸变域
 -> LiDAR z-buffer 硬锚点
 -> DA3 稠密候选和 LiDAR 对齐
 -> 当前帧/EWA/时序/多视角/TSDF 门控
 -> 共享 rig 的 SE(3) 目标位姿
 -> 七路几何 RGB-D 重投影
 -> 视觉补偿候选
 -> Kraw + D 重畸变
 -> RGB、depth、source map、unknown map、ABS DIFF、报告
```

当前最佳开关是 `SE3_CURRENT_EWA=1`、`SE3_RIG_DENSE_MULTIVIEW=1`、`SE3_INFORMATION_DOMAIN=1`，以及请求中的 `hybrid_3dgs=true`、`manifold_tsdf=true`。默认提交复现建议先关闭 `ai_inpaint`，这样不会因为外部 LaMa 权重缺失影响几何链路；需要展示最终视觉效果时再单独开启。

## 环境分层

| 环境 | 必需性 | 主要依赖 | 用途 |
|---|---|---|---|
| Viewer CPU | 必需 | Python 3.10、Flask、NumPy、OpenCV、SciPy、Pillow | 网页、投影、几何审计、CPU 基线 |
| Viewer CUDA | 可选 | Viewer 环境 + PyTorch/CUDA | 局部投影和栅格聚合加速 |
| DA3 | 预处理可选 | PyTorch、Depth Anything 3 源码和 checkpoint | RGB 对齐稠密深度候选 |
| 3DGS | 视觉可选 | 官方 Gaussian Splatting、CUDA rasterizer、模型 | visual-only 外观候选 |
| LaMa | 视觉可选 | `simple-lama-inpainting`、big-lama 权重 | residual RGB hole 修复 |

所有外部模型和源码都需要单独记录 URL、revision、许可证、checkpoint 文件名和 SHA256；提交包不包含模型权重。

## 运行方式

进入 `submission/03_engineering/l4-se_code` 后：

```bash
conda env create -f environment.submission.yml
conda activate l4-se-viewer

export SE3_STAGE=/data/temporal_sequence_2026-05-22-10-25-21
export SE3_OUT=/data/temporal_sequence_output_2026-05-22-10-25-21
export SE3_PORT=8142
export SE3_CURRENT_EWA=1
export SE3_RIG_DENSE_MULTIVIEW=1
export SE3_RIG_DENSE_MULTIVIEW_STEP=2
export SE3_DIRECTIONAL_BACKGROUND=1
export SE3_INFORMATION_DOMAIN=1
export SE3_AI_INPAINT=0
bash scripts/run_submission_demo.sh
```

浏览器访问 `http://127.0.0.1:8142/`。完整输入目录和 API 示例见 `l4-se_code/README.md`。

## 当前实测基线

frame 40、七路共享 rig、同一输入和同一输出契约下：

| 指标 | CPU | CUDA |
|---|---:|---:|
| 七路端到端耗时 | 32.068 s | 29.277 s |
| 加速比 | - | 1.10x |
| 平均 geometry coverage | 98.301% | 98.301% |
| 平均 final visual coverage | 100% | 100% |

因此提交默认使用 CPU 稳定路径，CUDA 保留为可选后端。不能把底层投影 kernel 的 3.53x/7.10x 直接写成全流程加速。

## 输出与科研边界

`reconstruction*` 和 depth 是几何审计结果；`final_distorted_polished`、3DGS、OpenCV、LaMa 是观看轨结果。视觉后处理不得修改 LiDAR anchor、深度、来源标签或 SE(3) 可用性。当前没有目标车型同步 GT，目标视角质量必须使用 no-GT proxy、LiDAR holdout、重投影一致性和人工检查描述，不能声称真实 PSNR/SSIM 已验证。
