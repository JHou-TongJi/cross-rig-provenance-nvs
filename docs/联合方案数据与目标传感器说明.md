# 联合方案数据与目标传感器说明

## 1. 数据来源

主数据为中安智联赛事参考道路采集数据。当前开发与候选展示使用的主要序列为 `2026-05-22-10-25-21`，通常每条序列包含 80 个关键帧、7 路相机和 1 路 `LIDAR_CONCAT`。

原始数据不随公开代码再次分发。提交包只放代码、配置、说明、索引和经授权可以提交的样例；原始 RGB、PCD、完整模型权重和运行缓存通过受控路径引用。

## 2. 单帧数据结构

```text
sequence/
├── Key_frames/
│   ├── camera_config/*.json
│   ├── <camera_name>/* image files
│   └── LIDAR_CONCAT/* point cloud files
└── ...
```

每帧需要建立 manifest，记录序列、源帧、时间戳、7 路 RGB 路径、LiDAR 路径、camera_config 路径、输出目标 rig、处理版本和随机种子。

## 3. 源车型传感器

`camera_config.json` 提供 `camera_external`、`camera_internal`、`width/height`、`rowMajor` 和相机文件对应信息。`camera_intric.yaml` 提供 `K_manual` 和 `D_manual=[k1,k2,p1,p2,k3]` Brown-Conrady 畸变参数。

主要分辨率为普通相机 `1920x1080`，前视宽/长焦相机 `3840x2160`。所有几何计算先在去畸变的 `K'` 域完成，最终展示再根据 `Kraw + D_manual` 恢复物理相机畸变域。

`LIDAR_CONCAT` 是主几何锚点，提供当前帧或时序点云。LiDAR 负责公制三维结构、遮挡顺序、深度锚点和几何可见性，不直接绘制最终 RGB。

## 4. 目标车型与 7V rig

主办方尚未提供完整目标车型 GT 时，采用开放式团队参考 preset：

```text
目标车尺寸（不含传感器）：3.70 m × 1.40 m × 2.00 m
目标相机数量：7
LiDAR 离地高度：0.50 m（团队估计，待确认）
```

该 preset 不是主办方实测参数。目标 rig 的 `K/D/T/width/height` 从配置文件读取，不能写死在算法中。当前配置：

```text
l4-se/config/target_l4_open_7v_3700x1400x2000.yaml
gcr-nvs-inference-only-20260826/configs/target_rigs/l4_all_up_20cm.yaml
```

这两个文件不是同一个层级的参数：`target_l4_open_7v_3700x1400x2000.yaml` 是比赛叙事中的开放式目标车型参考 preset；`l4_all_up_20cm.yaml` 是 GCR-NVS 当前用于推理审计的测试 rig，主要验证显式 `K/D/T`、整体 z 位移、结构 gate 和来源锁定。后者的当前输出分辨率为 1920×1080，不能在报告中写成主办方目标车的真实标定。

七路相机作为刚性模组整体移动。目标视角变换使用唯一的 `T_L_R_view`，每一路相机的相对安装关系由 `T_R_Ci_mount` 派生。

## 5. 数据用途隔离

| 数据/产物 | 用途 | 是否可作为真实 GT |
|---|---|---|
| 主办方源 RGB/PCD/config | 解析、几何重建、自测、展示 | 源观测，可作为锚点 |
| DA3 depth/confidence | 稠密表面候选 | 否，需 LiDAR 约束 |
| DINOv2/AnyUP feature | 语义/边界/对应 | 否 |
| T0 结构输出 | LiDAR 约束的结构估计 | 不是目标视角 GT |
| 视觉 gate 结果 | 有证据的背景恢复 | 不等同源观测 |
| RGB-D-S 生成区域 | residual hole 视觉补全 | 否，必须标记生成 |
| 80 帧真实输入 | 几何/时序输入 | 是源数据，不是目标视角 GT |
| 插值中间帧 | 连续展示或时序辅助 | 否，不得冒充实采帧 |
